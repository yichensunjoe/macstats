## Установка

[**Скачать MacStats.zip**](https://github.com/yichensunjoe/macstats/releases/latest/download/MacStats.zip) (около 2,5 МБ, macOS 15+ на Apple silicon)

1. Распакуйте и перетащите `MacStats.app` в `/Applications`
2. Первый запуск блокируется (**без нотаризации**): нажмите «Готово» в диалоге, затем Системные настройки → Конфиденциальность и безопасность → «Открыть всё равно»; либо снимите атрибут карантина в терминале. Причина и оба способа — в [заметках об установке](../install.md)
3. Панель появится на рабочем столе. Для виджета WidgetKit: правый клик по рабочему столу → «Изменить виджеты» → найдите «系统监视» (имя виджета в галерее)

```bash
# Необязательно: один раз снимите атрибут карантина, дальше хватит двойного клика
xattr -dr com.apple.quarantine /Applications/MacStats.app

# Или через Homebrew
brew tap yichensunjoe/macstats https://github.com/yichensunjoe/macstats
brew trust yichensunjoe/macstats      # Homebrew 5+ требует явного доверия сторонним tap
brew install --cask macstats
```

Проверка загрузки: `shasum -a 256 -c MacStats.zip.sha256` (контрольная сумма приложена к релизу).

«Мониторинг системы» и так показывает всё. Проблема в том, что это окно: его нужно открыть, выбрать вкладку, вывести вперёд. MacStats превращает те же шесть метрик в тёмную панель, которая постоянно висит на рабочем столе, снимает показания раз в секунду, перестраивает раскладку при изменении размера и вдобавок поставляет виджет WidgetKit — для тех, кто предпочитает держать маленький в сетке рабочего стола.

Это сознательно не большой дашборд. Метрик ровно пять, как в «Мониторинге системы», плюс загрузка GPU и занятая объединённая память, а также 90-секундный график, загрузка по ядрам, структура памяти и три процесса с наибольшим потреблением памяти. Основная работа была не в отрисовке, а в том, чтобы **каждое число совпадало с «Мониторингом системы»**. При сравнении в один и тот же момент память расходится не более чем на 0,2 ГБ, а накопленные счётчики диска и сети совпадают побайтно.

**Сожмите панель в полоску — включится минимальная раскладка.** Без карточек и графиков: шесть метрик в один ряд, как индикатор под строкой меню. Если панель становится слишком узкой для одного ряда, она складывается в сетку 3 × 2, и все шесть остаются видны. При обновлении раз в секунду приложение занимает около 1 % одного ядра и примерно 80 МБ памяти (замерено на arm64, macOS 26) — это самый лёгкий уровень отрисовки. При новой установке это форма по умолчанию; правый клик → «Развернуть в стандартную панель» открывает полную панель, а тот же пункт сворачивает её обратно.

> [!NOTE]
> Плавающая панель работает сразу. Копия в системной галерее виджетов требует действительной подписи Apple Development и установки в `/Applications` — это жёсткие требования `chronod`, а не настройки. См. [Расширение-виджет](#расширение-виджет).

## Сборка из исходного кода

Нужны macOS 15 или новее и инструменты командной строки Xcode (Swift 6). Сторонних зависимостей и проекта Xcode нет.

```bash
git clone https://github.com/yichensunjoe/macstats.git
cd macstats
bash scripts/bundle.sh          # сборка + упаковка + установка в /Applications + регистрация виджета
open /Applications/MacStats.app
```

При первом запуске в строке меню появляется небольшое значение `CPU · Память`, а на рабочем столе — панель.

- Левый клик по значку в строке меню: показать или скрыть панель
- Правый клик по панели: поверх всех окон, закрепить на столе, пропускать клики, интервал обновления (1 / 2 / 5 с), новый экземпляр
- Пустое место перетаскивается для перемещения, ручка в правом нижнем углу меняет размер; раскладка автоматически переключается между «Минимальной / Компактной / Стандартной / Подробной»
- Настройки хранятся в домене `com.macstats.app`, поэтому позиция и размер переживают перезапуск

## Что показывается

| Метрика | На панели | Как измеряется |
|---|---|---|
| CPU | Крупное общее значение + пользователь/система + график 90 с + полосы по ядрам | Разности `host_processor_info`, тот же источник, что у «Мониторинга системы» |
| Память | Занято / всего, полоса давления, состав App / Wired / сжатая, кэш | `vm_statistics64`, см. [Точность](#насколько-точно-совпадает-с-мониторингом-системы) |
| Энергия | Ватты из счётчика энергии CPU, уровень и состояние батареи | Разности `ri_energy_nj`; при отсутствии счётчика используется оценка по нагрузке с пометкой |
| Диск | Скорость чтения/записи, свободное место | Разности накопленных байт `IOBlockStorageDriver` |
| Сеть | Скорость отдачи/приёма, основной интерфейс | 64-битные счётчики `NET_RT_IFLIST2`; в скоростях не учитывается `lo0` |
| GPU | Крупное значение загрузки + 90-секундный график + занятая объединённая память / число ядер | `PerformanceStatistics` из `IOAccelerator` (`Device Utilization %`, `In use system memory`), тот же источник, что вкладка GPU «Мониторинга системы» |
| Процессы | Три самых прожорливых по памяти (пять в большом виджете) | `ri_phys_footprint` из `proc_pid_rusage` |

## Две поверхности

Один слой снятия показаний, два хоста:

| | Панель на столе | Системный виджет (WidgetKit) |
|---|---|---|
| Обновление | Перерисовка раз в секунду | Планируется системой, примерно раз в минуту |
| Позиция | Перетаскивается куда угодно, сколько угодно экземпляров | Сетка рабочего стола, следует за системой |
| Вход | Значок в строке меню / `open MacStats.app` | Правый клик по столу → «Изменить виджеты» → искать «MacStats» |
| Размер | Свободное изменение, четыре уровня раскладки | Малый / средний / большой / очень большой |
| Условия | Нет | Действительная подпись + установка в `/Applications` + точка входа `_NSExtensionMain` |

Нужно, чтобы «шевелилось», — берите панель. Нужно поставить рядом с другими виджетами — системный виджет. Оба читают один снимок, поэтому расходиться не могут.

## Насколько точно совпадает с Мониторингом системы

Метод: «Мониторинг системы» и панель на одном экране, значения «Мониторинга» читаются через API универсального доступа и сравниваются с показаниями, снятыми в тот же момент.

| Пункт | Результат |
|---|---|
| Память: занято / кэш / App / Wired / сжатая | В пределах 0,2 ГБ (сам «Мониторинг» держит картинку 5 секунд) |
| Диск: накопленное чтение / запись | Совпадает побайтно |
| Сеть: накопленный приём / отдача | Совпадает побайтно (десятичные ГБ) |
| Память процессов | 0,0 МБ при том же PID |
| CPU | 1–3 процентных пункта при стабильной нагрузке (сдвиг окна измерения) |

<p align="center">
  <img src="../monitor-compare.png" alt="Сверху: вкладка памяти в «Мониторинге системы». Снизу: панель MacStats в тот же момент" width="700" />
</p>

Для этого пришлось исправить три «очевидных» решения:

- **Накопленный сетевой трафик нужно брать из 64-битных счётчиков IFMIB.** `ifi_ibytes` в `NET_RT_IFLIST2` заполняет только младшие 32 бита, и после переполнения 122,9 ГБ трафика `lo0` на этой машине читались как 2,6 ГБ. В суммах `lo0` учитывается (как и в «Мониторинге»), а в столбцах скорости исключается — иначе петлевой трафик завышает скорость примерно в шестьдесят раз.
- **«Занято» — это не «App + Wired + сжатая».** Занятая память в «Мониторинге» = физическая − (свободная − speculative) − файловый кэш, а кэшированные файлы = файловый кэш + вытесняемые страницы. Реализовывать нужно их определение, а не интуитивное.
- **Энергия — это не «Влияние на энергию».** Этот столбец — безразмерная относительная оценка, воспроизвести её нельзя. Панель показывает физические ватты и подписывает плитку «счётчик энергии CPU», не смешивая единицы.

## Как это работает

Три слоя, ни один не зависит от интерфейса:

```
MacStatsCore  снятие показаний и пересчёты (чистая логика, покрыта тестами)
      ↓
WidgetData    снимок + кольцевая история на 90 точек
      ↓
SwiftUI-представления, общие для панели и расширения WidgetKit
```

- **Снятие показаний**: Mach (`host_processor_info`, `host_statistics64`), IOKit (статистика диска, источники питания), `sysctl(NET_RT_IFLIST2)`, `sysctl(vm.swapusage)`, libproc (`proc_listpids` / `proc_pid_rusage`). Только публичные API: без sudo, без отключения SIP, без приватных фреймворков.
- **Скорости — скользящее среднее последних пяти измерений**, что совпадает с 5-секундным окном «Мониторинга» и убирает мерцание.
- **Панель — это `NSPanel` уровня рабочего стола**: неактивирующая, на всех Spaces, никогда не забирает фокус, поэтому клик по ней не отправляет ваше текущее окно на задний план.
- **Данные не покидают машину**: нет сетевых запросов, телеметрии, аккаунтов, не читаются пользовательские файлы. Только системные счётчики через публичные API и один локальный JSON для расширения.

## Расширение-виджет

Расширение лежит в `MacStats.app/Contents/PlugIns/MacStatsWidget.appex`, для каждого размера своя раскладка. Чтобы оно появилось в галерее, нужны три вещи, и все три выяснились на практике:

1. **Расширению нужна действительная подпись и песочница.** `pkd` не принимает ad-hoc подписи, а appex без `com.apple.security.app-sandbox` даже с настоящим сертификатом молча отбрасывается с `rejecting; … plug-ins must be sandboxed`. Достаточно бесплатного сертификата личной команды (Xcode → Settings → Accounts → вход с Apple ID).
2. **Приложение должно лежать в `/Applications`, и зарегистрирована должна быть только одна копия.** `chronod` ищет хостов только в системной папке программ; при запуске из папки проекта или пользовательской папки Applications в журнале появляется `Ignoring restricted or unknown extension`. Двойная регистрация одного bundle id заставляет launchd создать два экземпляра XPC, и `chronod` перестаёт находить реальный процесс. `bundle.sh` устанавливает и чистит старые регистрации именно так.
3. **Точка входа appex должна быть `_NSExtensionMain`.** Это значение `LD_ENTRY_POINT` по умолчанию в Xcode; с точкой входа SwiftPM процесс запускается, печатает `main [WidgetBundle]`, но никогда не устанавливает XPC-сеанс с хостом и через ~15 мс объявляется мёртвым без отчёта о сбое. `src/Package.swift` закрепляет это через `linkerSettings`.

Расширение в песочнице не может читать `UserDefaults` основного приложения, поэтому данные идут снимком JSON: приложение перезаписывает его в папке Application Support каждые 2 секунды и дублирует в контейнер расширения, если тот существует; если свежего снимка нет, расширение снимает показания само.

Если `security find-identity -v -p codesigning` сообщает `0 valid identities`, обычно в связке ключей нет промежуточного сертификата Apple WWDR G3 — импортируйте `AppleWWDRCA-2030.cer` из ресурсов Xcode.

После изменения расширения поднимайте `CFBundleVersion`: `chronod` кеширует дескрипторы по версии и иначе продолжит показывать старое.

## FAQ

<details>
<summary><strong>Почему виджет обновляется примерно раз в минуту?</strong></summary>

WidgetKit — не цикл отрисовки, а плановый снимок: таймлайн отдаёт одну запись, и по истечении срока система спрашивает следующую. Хотя приложение запрашивает `reloadAllTimelines()` каждые 15 секунд, `chronod` ограничивает частоту бюджетом — в журнале видно `budgeted-1`. Сторонние виджеты не могут обновляться раз в секунду; системные часы — привилегия системы, а не расширений.

Для живых чисел используйте панель на рабочем столе, она перерисовывается каждую секунду.

</details>

<details>
<summary><strong>Почему WindowServer нет среди процессов с наибольшей памятью?</strong></summary>

Процессы других пользователей (например, `_windowserver`) недоступны для чтения: `proc_pid_rusage` возвращает EPERM, а `proc_pidinfo` — ноль байт. У «Мониторинга системы» есть entitlement Apple, поэтому он видит всё. Это граница прав, а не ошибка расчёта.

</details>

<details>
<summary><strong>Одно значение всё равно слегка отличается.</strong></summary>

«Мониторинг системы» обновляется раз в 5 секунд и показывает снимок прошлого обновления, панель — каждую секунду. При сравнении в один момент память может расходиться до 0,2 ГБ, а скорости и CPU — на сдвиг окна измерения. Сравните ещё раз через цикл обновления, и значения совпадут.

</details>

<details>
<summary><strong>Данные куда-нибудь отправляются?</strong></summary>

Нет. Никаких сетевых запросов, телеметрии, аккаунтов, пользовательские файлы не читаются. Только системные счётчики через публичные API и один локальный JSON для расширения.

</details>

<details>
<summary><strong>Работает ли на Intel Mac?</strong></summary>

Нет. Пакет выпускается только для Apple silicon (arm64): сборки для Intel и пути через Rosetta нет, поэтому на Intel Mac он не запускается.

</details>

## Известные ограничения

- **Системный виджет обновляется примерно раз в 60 секунд.** Это предел планирования WidgetKit, обойти его приложение не может.
- **Энергия — это физические ватты**, а не оценка «Влияние на энергию» из «Мониторинга». Единицы несопоставимы.
- **Список процессов охватывает только текущего пользователя** и сортируется по памяти: панель показывает три, слой измерений хранит до 24.
- **История только локальная и с точностью до минуты**: агрегируется по минутам и пишется в JSONL, хранится 7 / 30 / 90 дней на выбор. Облачной синхронизации и посекундного воспроизведения нет.
- **Оповещения только по трём показателям**: CPU / память / диск, после трёх подряд превышений порога, по умолчанию выключены. Температура, вентиляторы и отдельные процессы не отслеживаются.
- **Удалённого мониторинга нет**: все показания и история остаются на этом Mac и не уходят в сеть.
